# لعبة القنابل والجائزة (Bomb Prize Game)

لعبة تناوب محلية لشخصين على جهاز واحد، مبنية باستخدام Python وPygame. يجهّز
كل لاعب لوحة سرية بحجم 3×3 تحتوي على 3 قنابل وجائزة واحدة، ثم يحاول اللاعبان
كشف جائزة الخصم من دون اكتشاف ثلاث قنابل.

يحتوي المشروع على نسخة سطح مكتب، ونسخة متصفح مبنية بواسطة Pygbag، وغلاف ويب
باستخدام React وVinext لعرض اللعبة بصورة مناسبة للحاسوب والهاتف.

## نظرة سريعة

| العنصر | التفاصيل |
| --- | --- |
| نمط اللعب | لاعبان محليان بالتناوب على جهاز واحد |
| حجم اللوحة | 3×3 لكل لاعب |
| محتوى كل لوحة | 3 قنابل، جائزة واحدة، و5 خانات فارغة |
| الفوز | العثور على جائزة الخصم |
| الخسارة | اكتشاف القنبلة الثالثة تراكميًا |
| المنصات | سطح المكتب والمتصفحات الحديثة |
| التخزين | لا توجد حسابات أو قاعدة بيانات أو حفظ للمباريات |
| لغة الواجهة | الإنجليزية |

رسم اللعبة برمجي بالكامل ولا يعتمد على صور أو أصوات. بعد تثبيت الاعتماديات، لا
تحتاج نسخة سطح المكتب إلى اتصال بالإنترنت. أمّا نسخة الويب فتستخدم حاليًا بعض
ملفات تشغيل Pygbag من `pygame-web.github.io` وقد تحتاج إلى الإنترنت عند التحميل.

## قواعد اللعبة

1. يُدخل اللاعبان اسمين مختلفين؛ يبدأ صاحب الاسم الأول دائمًا.
2. يمسك اللاعب الأول الجهاز ويضع سرًا 3 قنابل وجائزة واحدة في لوحته.
3. يُمرَّر الجهاز إلى اللاعب الثاني ليجهّز لوحته بالطريقة نفسها.
4. في كل دور يختار اللاعب خانة مخفية واحدة من لوحة الخصم.
5. العثور على الجائزة ينهي المباراة بفوز اللاعب الحالي.
6. القنابل المكتشفة تتراكم على اللاعب؛ عند القنبلة الثالثة يخسر ويفوز خصمه.
7. الخانة الفارغة لا تضيف عقوبة، لكن الدور ينتهي بعد الاختيار الصحيح.
8. لا يمكن اختيار الخانة المكشوفة مرة ثانية، ولا يمكن كشف أكثر من خانة صحيحة
   في الدور الواحد. محاولة اختيار خانة مكشوفة لا تستهلك الدور، ويمكن بعدها
   اختيار خانة مخفية أخرى.

بعد كشف الخانة يجب الضغط على **End Turn**. ينطبق ذلك أيضًا على الحركة الحاسمة،
ثم تظهر شاشة النتيجة.

## المزايا

- شاشة خصوصية تطلب تمرير الجهاز قبل إعداد اللاعب الثاني وبين الأدوار.
- دعم الفأرة واللمس، مع حقول أسماء أصلية على متصفحات الهاتف.
- تخطيط متجاوب ومساحات آمنة لشاشات الهواتف ذات الحواف أو النتوءات.
- لون ثابت ومميز لكل لاعب خلال المباراة وإعادة اللعب.
- إعادة اللعب بالأسماء نفسها أو بدء مباراة جديدة.
- اختبارات لمنطق اللعبة، والتخطيط المتجاوب، وإدخال الهاتف، وسلامة حزمة الويب.

## المتطلبات

### نسخة سطح المكتب

- Python 3.9 أو أحدث لتشغيل اللعبة.
- Python 3.10 أو أحدث لتشغيل مجموعة الاختبارات كاملة.
- `pip` لتثبيت الحزم.

يختار `requirements.txt` تلقائيًا:

- `pygame` مع Python 3.9–3.13.
- `pygame-ce` مع Python 3.14 أو أحدث، مع واجهة الاستيراد نفسها `pygame`.
- `pytest` لتشغيل الاختبارات.

### نسخة الويب

- Python 3.12 موصى به لبناء Pygbag؛ فهو يطابق نسخة CPython/WASM المنشورة حاليًا.
- Pygbag بالإصدارات `>=0.9,<1` من `requirements-web.txt`؛ الإصدار المنشور
  والمتحقق منه حاليًا هو 0.9.3.
- Node.js 22.12 أو أحدث وnpm لتشغيل غلاف React/Vinext.
- متصفح حديث يدعم WebAssembly.

## التشغيل السريع على Windows

افتح PowerShell داخل مجلد المشروع ثم نفّذ:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python main.py
```

إذا منع PowerShell تفعيل البيئة الافتراضية، يمكن تشغيل مفسّرها مباشرة:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

على macOS أو Linux يختلف أمر التفعيل فقط:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

يعتمد نجاح تثبيت Pygame على توفر حزمة مناسبة للنظام والمعمارية المستخدمة.

## التحكم

| المكان | التحكم |
| --- | --- |
| الأزرار وخانات اللوحة | زر الفأرة الأيسر أو اللمس |
| حقول الأسماء | النقر أو اللمس لتحديد الحقل |
| التنقل بين الاسمين | `Tab` |
| حذف حرف | `Backspace` أو `Delete` |
| متابعة شاشة الأسماء | `Enter` بعد إدخال اسمين صالحين |
| الرجوع إلى القائمة | `Escape` من معظم الشاشات |

في القائمة الرئيسية، يغلق `Escape` اللعبة، بينما يعيد المستخدم من صفحة التعليمات
إلى القائمة. الرجوع إلى القائمة أثناء المباراة يلغي المباراة الحالية من دون
رسالة تأكيد.

شروط الأسماء:

- الاسمان مطلوبان ويجب أن يكونا مختلفين دون اعتبار حالة الأحرف.
- تُحذف المسافات من بداية الاسم ونهايته عند المتابعة.
- الحد الأقصى لكل اسم هو 15 محرفًا.

أثناء إعداد اللوحة يبدأ وضع **Select Bomb** تلقائيًا. اختر **Select Bomb** أو
**Select Prize** ثم اضغط خانة فارغة لوضع العنصر. الضغط على خانة مشغولة يزيل
محتواها، و**Clear** يمسح اللوحة كاملة، ولا يتفعّل **Confirm** قبل وضع 3 قنابل
وجائزة واحدة.

## تشغيل نسخة Pygbag مباشرة

ثبّت متطلبات اللعبة وأداة الويب:

```powershell
py -3.12 -m pip install -r requirements.txt
py -3.12 -m pip install -r requirements-web.txt
```

شغّل Pygbag من المجلد الأب للمشروع، لأن الوسيط الأخير هو مجلد التطبيق:

```powershell
cd ..
py -3.12 -m pygbag bomb_prize_game
```

ثم افتح <http://localhost:8000>. إذا كان اسم مجلد المشروع مختلفًا، استبدل
`bomb_prize_game` باسمه الفعلي.

على macOS أو Linux استخدم `python3.12 -m` بدل `py -3.12 -m` في أوامر Pygbag.

## تشغيل غلاف الويب React/Vinext

غلاف الويب يعرض حزمة Pygbag الموجودة في `public/game/index.html` داخل `iframe`.

```bash
npm ci
npm run dev
```

افتح <http://localhost:3000>.

لبناء نسخة الإنتاج:

```bash
npm run build
```

تُكتب مخرجات Vinext في `dist/client` و`dist/server`.

> **مهم:** لا يعيد `npm run dev` أو `npm run build` بناء كود Python. يعرض الغلاف
> الحزمة المنشورة مسبقًا داخل `public/game`. لذلك لن تظهر تعديلات ملفات Python
> في هذا الغلاف حتى تُعاد حزم اللعبة وتُزامن ملفات النشر.

## إنشاء حزمة Pygbag للنشر

من جذر المشروع نفّذ:

```powershell
py -3.12 -m pygbag --archive main.py
```

يجهّز الأمر ملفات الويب في `build/web/` وينشئ أرشيفًا في `build/web.zip`.
يستبعد `pygbag.ini` مجلدات التطوير والاختبارات وغلاف الويب من حزمة Python.

ملفات النشر الحالية مخصصة أكثر من المخرجات الافتراضية لـPygbag، ويجب عند
تحديثها الحفاظ على الشروط التالية التي تتحقق منها الاختبارات:

- تطابق `public/index.html` و`public/game/index.html`.
- تطابق ملفي `bomb_prize_game.apk` مع الحزمة المضمّنة بصيغة Base64 في HTML.
- بقاء إعدادات viewport وsafe area وطبقات حقول الهاتف سليمة.
- تحديث رقم كسر الذاكرة المؤقتة في `app/page.jsx` عند الحاجة بعد النشر.

لا يوجد حاليًا سكربت داخل المستودع يزامن `build/web` مع `public` أو يعيد تضمين
الحزمة في HTML تلقائيًا؛ هذه خطوة نشر يدوية. لا تنسخ مخرجات Pygbag الافتراضية
فوق `public` مباشرة، لأنها لا تتضمن تخصيصات التحميل والهاتف الحالية. بعد أي
تحديث يدوي شغّل مجموعة الاختبارات كاملة قبل النشر.

امتداد `.apk` هنا هو أرشيف موارد خاص بـPygbag، **وليس تطبيق Android قابلًا
للتثبيت**.

## الاختبارات والتحقق

شغّل الاختبارات من جذر المشروع:

```bash
python -m pytest -q
```

وتحقق من ملفات التطبيق المكتوبة بلغة Python:

```bash
python -m compileall -q main.py game screens
```

وتحقق من بناء غلاف الويب:

```bash
npm run build
```

تغطي الاختبارات الحالية:

- حدود القنابل والجائزة ومنع تداخل العناصر.
- جاهزية اللوحتين، وتبديل الأدوار، ومنع اختيار الخلية نفسها مرتين.
- الفوز بالجائزة والخسارة عند القنبلة الثالثة.
- إعادة اللعب ومسح حالة المباراة مع الحفاظ على الأسماء والألوان عند الطلب.
- أحجام سطح المكتب والهاتف العمودي.
- مزامنة حقول الأسماء الأصلية على الهاتف مع Pygame.
- سلامة صفحات الويب والمساحات الآمنة وتزامن حزمة Pygbag المنشورة.

الحالة التي تم التحقق منها أثناء تحديث هذا التوثيق: **25 اختبارًا ناجحًا**، مع
نجاح فحص Python وبناء Vinext.

## معمارية المشروع

يفصل المشروع منطق اللعبة عن واجهات العرض:

```text
إدخال المستخدم
      │
      ▼
screens/*  ── actions ──>  main.py (آلة الحالات)
      │                           │
      └──────────────> game/* <───┘
                              │
                              ▼
                    Board / Player / GameManager
```

تسلسل الشاشات الرئيسي:

```text
menu
  └─> names
       └─> setup_0
            └─> pass
                 └─> setup_1
                      └─> pass
                           └─> gameplay <─> pass
                                └─> result
```

كل شاشة تتعامل مع الإدخال عبر `handle_event()` وتعيد إجراءً رمزيًا، بينما يتولى
`GameApplication` في `main.py` الانتقال بين الشاشات. بهذه الطريقة تبقى قواعد
اللعبة داخل `game/` ولا تعتمد مباشرة على تفاصيل العرض.

## أهم الإعدادات

توجد الإعدادات العامة في `game/settings.py`:

| الثابت | القيمة الحالية | الوظيفة |
| --- | ---: | --- |
| `BOARD_SIZE` | 3 | عدد الصفوف والأعمدة |
| `BOMBS_REQUIRED` | 3 | عدد القنابل في اللوحة وحد الخسارة |
| `PRIZES_REQUIRED` | 1 | العدد المقصود للجوائز |
| `MAX_NAME_LENGTH` | 15 | الحد الأقصى لطول الاسم |
| `FPS` | 60 | معدل الإطارات المستهدف |
| `WINDOW_WIDTH × WINDOW_HEIGHT` | 900×700 عادةً | الحجم المنطقي لسطح المكتب |

يستخدم الهاتف العمودي بعرض 600 بكسل أو أقل تخطيطًا منطقيًا بحجم 480×700.

لا يُنصح بتغيير `BOARD_SIZE` أو `PRIZES_REQUIRED` وحدهما: بعض مواضع الواجهة
ثابتة، كما أن منطق اللوحة الحالي يفرض جائزة واحدة مباشرة. أي تغيير في قواعد
اللوحة يجب أن يرافقه تعديل للمنطق والتخطيط والاختبارات.

## Raspberry Pi

لا يعتمد منطق اللعبة على Windows. على Raspberry Pi OS حديث يمكن تجربة:

```bash
sudo apt update
sudo apt install python3-pygame python3-pytest
python3 main.py
```

يمكن بدلًا من ذلك استخدام بيئة افتراضية و`requirements.txt` إذا كانت حزم
Pygame المناسبة متاحة لإصدار Python ومعمارية النظام. نسخة سطح المكتب أنسب من
حزمة الويب للأجهزة محدودة الموارد مثل Raspberry Pi 3.

## حدود النسخة الحالية

- لاعبان محليان فقط؛ لا يوجد لعب شبكي أو خصم بالذكاء الاصطناعي.
- لا يوجد حفظ أو استئناف أو سجل نتائج.
- الواجهة داخل اللعبة إنجليزية فقط.
- الخصوصية تعتمد على تمرير الجهاز عند ظهور شاشة التنبيه، وليست حماية تقنية.
- التحكم بلوحة المفاتيح لا يشمل التنقل بين أزرار اللعبة أو خلايا اللوحة.
- إعادة اللعب بالأسماء نفسها تعيد إعداد اللوحتين والإحصاءات من الصفر.
